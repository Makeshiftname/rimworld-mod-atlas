# 收录区 —— mod 分析记录标准

> **开始分析任何一个 mod 之前，先读这一页。**
> 本文件是收录区的唯一标准本体，不依赖仓库其他文档。
> （本区不在 `docs/knowledge/` 体系内，也不在 `AGENTS.md` 的指路范围内，
> 所以**必须主动来看**，不会自动被发现。）

---

## 0. 这个区是干什么的

**收录**用户自己挑选的、有意义的 RimWorld mod，为每个写一份分析记录。

**当前阶段不做的事**：不批量修改 mod，不替用户动游戏目录里的任何文件。
改动只是记录里的**可选章节**（见 §3），等用户说"改"的时候再针对性动手。

> 2026-10-16 定：曾一度把这里叫 `修改/`，但实际收录的 mod 里三成零修改项，
> 名字和用法对不上。改名 `收录/`，"修改"降级为记录里的一个可选章节。

---

## 1. 术语

| 词 | 含义 | 不要混用的近似说法 |
|---|---|---|
| **收录** | 选一个 mod 进本区并写记录 | ≠ 归档（不是打包代码），≠ 修复 |
| **记录** | `收录/<mod目录>/README.md` 这一份分析 | ≠ 改后的 mod 本身 |
| **它是什么** | 这个 mod 的功能、数值、手法——它自己的事实 | ≠ 我对它的评价 |
| **怎么验的** | 我的核验方法 + **阳性对照** + **自查纠错** | ≠ 结论本身 |
| **阳性对照** | 证明核验工具本身可信的那个已知有效样例 | 见 §4 |
| **自查纠错** | 本次分析里我自己的工具犯过错、被纠正的记录 | 见 §4 |
| **可复用结论** | 脱离本 mod 仍然成立的通用经验 | ≠ 本 mod 的专属细节 |
| **修改建议** | 待办项，可选章节，没有就**删掉整节** | ≠ 已执行的改动 |
| **提炼** | 把攒够的记录里的通用结论批量沉淀进主题笔记 | 见 §6 |

## 2. 目录命名规则

收录目录名 **必须能对上** `F:\Games\GBL\rimworld\Mods\` 下的源目录：

| 源目录名形态 | 收录目录名 | 例子 |
|---|---|---|
| 有语义（中文名、自带序号） | **直接用源名** | `1 美南烛` → `收录/美南烛/` |
| 源名带无意义前后缀 | **可缩短，但须能唯一识别** | `1~11岁美狐贴图修正(本体更新修复版)` → `收录/1~11岁美狐贴图修正/` |
| 是无语义的工坊 ID | **源 ID + 可读后缀** | `717575199` → `收录/717575199-MiscTraining/` |

两套并存是有意为之：源名本身能读的就不加工，源名只是一串数字的才补后缀。

**缩短的写法必须登记到 `tools/kb/check_records.py` 的 `DIR_ALIASES`**，
否则校验会判成"找不到对应源目录"。校验时按三种形态依次尝试：
精确匹配 → `工坊ID-可读名` → `DIR_ALIASES` 显式对照。

## 3. 记录骨架

**四个必答锚点**，标题固定、不加编号：

```markdown
# <mod 名称> — 分析记录

## 身份卡

## 它是什么

## 怎么验的

## 可复用结论

## 修改建议        ← 可选；没有待办就整节删掉，不要留空壳
```

- mod 专属的细节建议写成 `###` 三级标题，**挂在对应锚点下面**；确实撑不起一个锚点时，
  可以保留成独立的二级章节，**放在「怎么验的」与「可复用结论」之间**。
- 需要额外维度（上下游、冲突面、依赖图）时，同样放在「怎么验的」之后。

### 3.1 各锚点必答内容

| 锚点 | 必答内容 |
|---|---|
| **身份卡** | 名字 / packageId / 作者 / 授权 / 规模（文件数·体积）/ 类型 / 支持版本 / 外部依赖及其安装状态 |
| **它是什么** | 功能、数值、手法。**只写这个 mod 自己的事实**，不下评价 |
| **怎么验的** | ① 核验方法（可复现）② **阳性对照**（证明工具可信的样例）③ **自查纠错**（我自己的工具犯过什么错、怎么发现的） |
| **可复用结论** | 脱离本 mod 仍成立的通用经验，写成可迁移的判断规则 |
| **修改建议**（可选） | 分优先级列出待办。没有就删节 |

### 3.2 授权必须单独核实

- `About.xml` 有没有禁再分发声明
- **禁再分发的 mod**：收录区只存结论，不收录其 Def 原文 / 贴图 / DLL
- 有 LICENSE 文件的记下许可证（Harmony 是 MIT，与 yukiyuki 系列的"禁止再分发"相反）

## 4. 核验的四档深度

按 mod 规模分档，**选最高适用的一档**：

| 档 | 触发条件 | 手法 |
|---|---|---|
| ① 极小 | 2–4 文件、纯 XML | 精读 + 交叉引用 + 贴图核实 |
| ② 中 | ~15 文件、单一机制 | 精读 + 逐文件 diff + IL 反射 |
| ③ 大 | 30+ 文件 / 150+ Def | **脚本批扫**（收集全部 defName → 查 ParentName / 引用字段 / texPath）再精读关键片段 |
| ④ 基础设施 | 它本身是别人的地基 | 自身分析 + **顺藤摸瓜查依赖图**（谁依赖它 / 谁自带重复副本 / 与谁冲突） |

**底线：无论哪一档，§3 的四个必答锚点必须答完。分档只影响"查多深"，不影响"答不答"。**

第 ④ 档产出最高（Harmony 那份靠它挖出了全库 85 个重复副本），看到下列任一信号就升档：
`packageId` 被大量 mod 声明为依赖 / 自带公共库 / 在传输管线上（Harmony、翻译框架、事件框架）

## 5. 阳性对照与自查纠错（硬性要求）

这是 2026-10-16 那轮分析里最值钱的部分——**当天我的核验工具出了 4 次错，每次都差点给出方向相反的结论，全靠对照发现**：

| 错误 | 怎么发现的 |
|---|---|
| `Select-String -List` 只返回**首个**匹配文件 → 误报"BaseBullet 只在 Anomaly 里" | 去掉 `-List` 重查，Core 里就在 |
| 目录列表把文件大小四舍五入成 KB → 10 字节显示为 `0` → 误判 5 份记录的 `PublishedFileId` 是空文件 | 直接读 `[System.IO.File]::ReadAllBytes($p).Length` |
| 抽象父类正则 `Name="..."[^>]*Abstract="true` 假设了属性顺序 → 漏掉 `Abstract` 在前的写法 | 穷举所有声明形式 |
| 跨根目录比对贴图只加 `Textures/` 前缀，而游戏内是 `Core/Textures/` → 原版路径全判缺失 | 按文件名后缀反查 |

**规则**：

1. **任何"扫描/正则/grep 得出的 0 命中或全缺失"结论，必须先证明同一个工具能在已知有效的样例上命中**，否则 0 不可信。
2. **报"文件是空的"之前读字节数**，不要看 KB 化的列表输出。
3. **属性顺序不能假设**，或用两次独立匹配。
4. **自查纠错必须写进「怎么验的」**，不要悄悄改掉结论了事——留着才能防止后人重走。

## 6. 与主题笔记的关系：定期批量提炼（**按需触发**）

记录的「可复用结论」是**原料**；`docs/knowledge/` 的主题笔记是**成品**。

> **提炼由用户触发。** 不设固定批次、不设自动触发。
> 用户说"提炼"时才做——把手上攒的记录里的跨 mod 通用结论批量沉淀进 `docs/knowledge/*.md`，
> 并清理两边打架的说法。

已知的待提炼项（攒着，下次提炼时处理）：

- `docs/knowledge/cross-version-structure.md:34` 写着"现仓库倾向弃用 LoadFolders"，

- `docs/knowledge/README.md` 与 `AGENTS.md` 里的 mod 计数（"83 个 / 收集 82"）已过期。

## 8. 校验

```bash
python tools/kb/check_records.py     # 收录区专属门禁，退出码 0 = 通过
```

检查四项：
1. 四个必答锚点章节是否齐全
2. 收录目录名能否对上 Mods 源目录
3. 记录里出现的 Mods 绝对路径是否真实存在
4. 本索引表是否覆盖全部记录

> 注意：`check_links.py` **不覆盖本区**（它只扫 `AGENTS.md` + `docs/knowledge/*.md` + `mod-index.md`）。
> 报告"门禁通过"时别把它算进去。
